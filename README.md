## 🔍 Overview

SpaceGuard AI is a full-stack, AI-powered web application that transforms raw spacecraft telemetry into **actionable mission insights**. It continuously ingests sensor readings across 9 parameters, runs a multi-stage ML pipeline, and delivers structured natural-language explanations generated by **IBM Granite** — all within a polished, dark-themed mission-control dashboard.

```
Raw Telemetry  ──►  Anomaly Detection  ──►  Risk Scoring  ──►  Granite Explanation  ──►  Operator Action
```

### 🚨 Problem Statement

Spacecraft generate continuous streams of telemetry — temperature, battery voltage, fuel level, radiation, pressure, signal strength, velocity, and power consumption. Mission operators must analyze this data quickly to catch abnormal behavior before it becomes critical. Traditional dashboards display raw graphs but offer **no intelligence layer** to flag problems, explain causes, or recommend actions.

### 💡 Solution

SpaceGuard AI closes that gap by:

1. Ingesting real-time or CSV-uploaded spacecraft telemetry
2. Running Isolation Forest multi-parameter anomaly detection on every record
3. Computing a transparent health score (0–100) with a full score breakdown
4. Predicting future parameter values using linear regression trend analysis
5. Calling IBM Granite via watsonx.ai to generate structured natural-language explanations
6. Automatically creating prioritized, deduplicated alerts for operator attention
7. Providing a conversational AI mission assistant grounded in live database context

## 🧠 AI Architecture

### Full Pipeline

```
 Spacecraft Telemetry Record
           │
           ▼
 ┌─────────────────────────┐
 │  Django REST Serializer  │  ← Validates all 9 sensor fields
 └─────────────────────────┘
           │
           ▼
 ┌─────────────────────────┐
 │    Isolation Forest      │  → anomaly_score · severity · suspicious_parameters
 │  ai/anomaly_detector.py  │  → affected_subsystem (THERMAL / ELECTRICAL / COMMUNICATION / …)
 └─────────────────────────┘
           │
           ▼
 ┌─────────────────────────┐
 │   Linear Regression      │  → trend · predicted_value · time_to_threshold
 │    ai/predictor.py       │  → plain-English warning messages
 └─────────────────────────┘
           │
           ▼
 ┌─────────────────────────┐
 │      Risk Engine         │  → health_score (0–100) · risk_level · score_breakdown
 │    ai/risk_engine.py     │
 └─────────────────────────┘
           │
           ▼
 ┌─────────────────────────┐
 │  IBM Granite (watsonx)   │  → detected_problem · evidence · recommended_action
 │  ai/granite_service.py   │  → Rule-based fallback if API unavailable
 └─────────────────────────┘
           │
           ▼
 Alert Service  +  Dashboard  +  REST API Response
```

---

### 🔬 Anomaly Detection — Isolation Forest

- Trained on historical spacecraft telemetry stored in the database
- Detects **multi-parameter anomalies** that single-threshold rules would miss
- Outputs: `anomaly_score`, `severity`, `suspicious_parameters`, `affected_subsystem`
- Hard safety-threshold layer supplements the ML model for critical limit violations

**Subsystem Classification:**

| Suspicious Parameter | Mapped Subsystem |
|---|---|
| `temperature` | THERMAL |
| `battery_voltage`, `battery_current`, `power_consumption` | ELECTRICAL |
| `signal_strength` | COMMUNICATION |
| `fuel_level`, `pressure` | PROPULSION |
| `velocity` | NAVIGATION |
| `radiation` | RADIATION |

---

### 💯 Health Scoring — Explainable Rule-Based + ML

Every record starts at **100** with transparent deductions logged to `score_breakdown`:

| Component | Deduction Logic |
|---|---|
| Anomaly severity | NORMAL: 0 · LOW: −5 · MODERATE: −15 · HIGH: −30 · CRITICAL: −50 |
| Threshold violations | Warning: −2 pts each · Critical breach: −10 pts each |
| Trend penalty | Up to −10 pts when critical params trend toward limits |

**Risk Level Classification:**

| Score | Risk Level | Category |
|:---:|:---:|:---:|
| 90 – 100 | 🟢 NORMAL | Excellent |
| 75 – 89 | 🔵 LOW | Good |
| 60 – 74 | 🟡 MODERATE | Moderate Risk |
| 40 – 59 | 🟠 HIGH | High Risk |
| 0 – 39 | 🔴 CRITICAL | Critical |

---

### 📈 Predictive Monitoring — Linear Regression

- Fits a linear model over the **last 20 telemetry records** per mission
- Computes slope to estimate **time-to-threshold** for `temperature`, `battery_voltage`, `signal_strength`
- Penalty applied when abs(slope) > 0.1 and the trend moves toward a danger limit
- Generates plain-English warning messages surfaced directly on the dashboard

---

### 🤖 Generative AI — IBM Granite (`ibm/granite-13b-instruct-v2`)

- Context assembled **entirely from database-sourced values** — Granite is never given latitude to invent sensor readings
- Prompt constraint: *"Use ONLY the telemetry values provided below. Do NOT invent or estimate any sensor readings."*
- Structured output parsed into 6 fields: `detected_problem`, `affected_subsystem`, `severity`, `evidence`, `possible_cause`, `recommended_action`
- **Rule-based fallback** returned on any API failure, clearly labeled `"Rule-Based Fallback"`
- **Mission Assistant** builds live context (latest telemetry + health score + active alerts + latest analysis) and passes it with the operator's question

### Data Model

```
Mission ──< Telemetry ──< AIAnalysis
   └──< Alert
```

| Model | Key Fields |
|---|---|
| `Mission` | `name`, `spacecraft_name`, `launch_date`, `status` (ACTIVE / STANDBY / COMPLETED / LOST) |
| `Telemetry` | `timestamp`, `temperature`, `battery_voltage`, `battery_current`, `fuel_level`, `radiation`, `pressure`, `signal_strength`, `velocity`, `power_consumption`, `is_anomaly`, `anomaly_score` |

| `Alert` | `mission` (FK), `telemetry` (FK), `subsystem`, `severity`, `status` (NEW / INVESTIGATING / RESOLVED), `description` |

## ⚙️ IBM Granite / watsonx.ai Integration

Implemented in [`SpaceGuard-AI/backend/ai/granite_service.py`](SpaceGuard-AI/backend/ai/granite_service.py).

### How it works

```
1. Assemble JSON context from DB values only (telemetry + anomaly result + health score + predictions)
         │
         ▼
2. Inject into prompt with strict instruction: "Do NOT invent or estimate any sensor readings"
         │
         ▼
3. Exchange IBM API Key → IAM Bearer Token  (POST iam.cloud.ibm.com/identity/token)
         │
         ▼
4. Call watsonx.ai text generation endpoint  (POST /ml/v1/text/generation)
         │
         ▼
5. Parse response into 6 structured fields
         │
         ├── Success  → return parsed explanation  (labeled "IBM Granite")
         └── Failure  → return rule-based fallback (labeled "Rule-Based Fallback")
```

### Granite Output Fields

| Field | Description |
|---|---|
| `detected_problem` | Plain-English description of what is wrong |
| `affected_subsystem` | THERMAL / ELECTRICAL / COMMUNICATION / PROPULSION / NAVIGATION |
| `severity` | NORMAL / LOW / MODERATE / HIGH / CRITICAL |
| `evidence` | Specific telemetry readings that triggered the analysis |
| `possible_cause` | Most likely technical explanation |
| `recommended_action` | Concrete steps for mission operators |

### Mission Assistant

The conversational assistant builds a context object from the live database (latest telemetry, health score, active alerts, latest AIAnalysis) and forwards it with the operator's natural-language question to IBM Granite.


## 🗂️ API Reference

### Missions

| Method | Endpoint | Description |
|:---:|---|---|
| `GET` | `/api/missions/` | List all missions |
| `POST` | `/api/missions/` | Create a new mission |
| `GET` | `/api/missions/{id}/` | Retrieve mission detail |
| `GET` | `/api/missions/{id}/health/` | Current health score + `score_breakdown` |
| `GET` | `/api/missions/{id}/anomalies/` | All anomalous telemetry records |
| `GET` | `/api/missions/{id}/alerts/` | Active alerts for this mission |
| `POST` | `/api/missions/{id}/analyze/` | **Run the full AI pipeline** on the latest record |
| `POST` | `/api/missions/{id}/assistant/` | Send a question to the AI Mission Assistant |

### Telemetry

| Method | Endpoint | Description |
|:---:|---|---|
| `POST` | `/api/missions/{id}/telemetry/` | Ingest a single telemetry record |
| `POST` | `/api/missions/{id}/telemetry/upload/` | Bulk upload via CSV file |

### Alerts

| Method | Endpoint | Description |
|:---:|---|---|
| `GET` | `/api/alerts/` | All alerts (filterable by `status`, `mission`) |
| `PATCH` | `/api/alerts/{id}/` | Update alert status: `NEW` → `INVESTIGATING` → `RESOLVED` |

### Example Requests

**Ingest a single telemetry record:**

```bash
curl -X POST http://localhost:8000/api/missions/1/telemetry/ \
  -H "Content-Type: application/json" \
  -d '{
    "timestamp": "2025-07-15T12:00:00Z",
    "temperature": 28.5,
    "battery_voltage": 27.8,
    "battery_current": 8.2,
    "fuel_level": 72.0,
    "radiation": 13.5,
    "pressure": 101.1,
    "signal_strength": -72.0,
    "velocity": 7.65,
    "power_consumption": 255.0
  }'
```

**Run the full AI analysis pipeline:**

```bash
curl -X POST http://localhost:8000/api/missions/1/analyze/
```

**Ask the Mission Assistant:**

```bash
curl -X POST http://localhost:8000/api/missions/1/assistant/ \
  -H "Content-Type: application/json" \
  -d '{"question": "Which subsystem has the highest risk right now?"}'
```
